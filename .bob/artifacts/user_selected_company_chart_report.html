Architecture & Feasibility Report

Feature Assessment: User-Selected Company Chart

Target: jrichardson1110/finance-app | Issue #1 | Branch: feature/user-selected-company-chart

1. Executive Summary & Issue Context

GitHub Issue #1: Add a graph for a user selected company

Status: Open | Author: jrichardson1110

Core Objective: Provide dashboard users with the ability to dynamically select or enter a ticker symbol to compare against benchmark data, while ensuring zero regression to the existing fixed competitor comparisons (IBM vs. MSFT, ORCL, SAP, CRM).

2. Acceptance Criteria

ID Domain Requirement Specification
AC-01 Input & Validation Provide an accessible text input / selector for symbol entry. Normalize input automatically (trim whitespace, uppercase transformation).
AC-02 Client Validation Validate input against symbol regex pattern (/^[A-Z0-9.-]{1,10}$/). Reject malformed input prior to network dispatch with an inline guidance prompt.
AC-03 Dynamic Querying Fetch price series data for the selected symbol across the currently active time window (day, week, or quarter).
AC-04 Visualization Render a dedicated chart or rebased comparative trend line displaying the user-selected company alongside IBM baseline data.
AC-05 Error Feedback If the symbol does not exist (SYMBOL_NOT_FOUND / 404), display a clear, non-technical error notification without crashing parent containers.
AC-06 Non-Regression Existing fixed comparison views (Quote Cards, Change Bar Charts, Relative Performance Cards, Rank Highlights) remain unaffected.

3. Architecture & System Impact Analysis

Data Service Layer (Server & Proxy Client)

The existing backend architecture is already designed to support arbitrary ticker lookups without schema or endpoint alterations:

  • GET /api/history?symbol=:symbol&window=:window: Accepts any symbol matching SymbolSchema.
  • GET /api/quotes?symbols=:symbols: Accepts comma-separated tickers up to MAX_SYMBOLS_PER_REQUEST (10).
  • createHttpFinanceService: Already exposes getHistory(symbol, window) and translates backend error codes to typed FinanceServiceError instances.

State Management Strategy

To avoid polluting the fixed competitor dataset, query states must be completely isolated:

Decoupled Query Boundary

Do not inject dynamic symbols into the core useWindowSeries hook. Instead, implement a dedicated hook (e.g. useCustomCompanySeries) using TanStack Query:

const customQuery = useQuery({
  queryKey: ['customHistory', selectedSymbol, window],
  queryFn: ({ signal }) => financeService.getHistory(selectedSymbol, window, signal),
  enabled: Boolean(selectedSymbol && isValidSymbol(selectedSymbol)),
  staleTime: WINDOW_CONFIG[window].staleTimeMs,
});

UI Component Hierarchy

  • CustomCompanySearchCard: Encapsulates user input, submit/reset triggers, client-side validation errors, loading skeletons, and upstream error displays.
  • DashboardPage: Mounts the custom card alongside existing view containers while feeding the shared active window state.
